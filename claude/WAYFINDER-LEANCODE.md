# Workflow: plan → build

**กติกาหลัก: ฝั่งวางแผนตัดสินใจ, ฝั่ง build ลงมือ. ห้ามสลับ, ห้ามข้ามขั้น**

วางแผนมาจาก skill ไหนก็ได้ — `wayfinder` เป็นตัวที่ตรงที่สุดเมื่อมี map อยู่แล้ว แต่ไม่ใช่ทางเดียว ส่วนฝั่ง build **ไม่ต้องเรียกชื่อ**: พอ decision ครบและก้าวถัดไปคือการแก้โค้ด skill ที่รับงาน build จะถูกเลือกจาก description ของมันเอง

## เลือก skill ยังไง

ก่อนเริ่มงานที่ไม่ใช่คำถามสั้น ๆ ให้เช็คตามลำดับนี้:

1. **มี `.wayfinder/map.md` ในโปรเจกต์ไหม** (หรือ repo พี่น้องที่เกี่ยวข้อง)
   → มี: `wayfinder` โหมด Work — โหลด map, health check, claim ticket, resolve ทีละใบ
2. **งานใหญ่เกินหนึ่ง session / ยังไม่รู้ว่าจะทำยังไง / มีคำถามค้างหลายข้อ**
   → วางแผนก่อน อย่าเพิ่งเขียนโค้ด (`wayfinder` โหมด Chart หรือ planner ตัวอื่นที่เหมาะกว่า)
3. **ทางชัดแล้ว รู้ว่าต้องแก้อะไรตรงไหน**
   → ลงมือ build ได้เลย ไม่ต้องประกาศว่าจะเรียก skill ตัวไหน

ถ้าไม่แน่ใจว่าข้อ 2 หรือ 3 — เลือกวางแผนไว้ก่อน แล้วถามผู้ใช้ 1 คำถาม

## เส้นแบ่ง

| | ฝั่งวางแผน | ฝั่ง build |
|---|---|---|
| ผลลัพธ์ | decision + spec ที่ build ได้ | โค้ดที่รันได้จริง |
| เขียนโค้ดไหม | prototype ที่ทิ้งได้เท่านั้น | ใช่ |
| ที่อยู่ของงาน | `.wayfinder/map.md` + tickets | `HANDOFF.md` + diff |

- อยู่ฝั่งวางแผนแล้วรู้สึก "อยากลงมือเขียนเลย" = ถึงขอบ map แล้ว → **หยุด ส่งต่อ** ไม่ใช่เขียนต่อเอง
- อยู่ฝั่ง build แล้วเจอคำถามที่ตอบไม่ได้ = fog → **โยนกลับไปหาคนที่เรียกมันมา** พร้อมคำถาม ตัวเลือก และตัวที่จะเลือก — ไม่ใช่เดาแล้วเขียน และไม่ใช่เลือก skill ถัดไปให้เขาเอง
  - คนเรียกเป็น planner → เปิดเป็น ticket/fog ต่อในนั้น · คนเรียกเป็นผู้ใช้ → ถามผู้ใช้ตรง ๆ
  - งานที่ build เสร็จและ verify แล้วอยู่ต่อได้ ไม่ต้องรื้อ กลับมาต่อจาก step เดิมตอนได้คำตอบ

## ส่งต่อ (handoff)

map จบเมื่อ frontier ว่าง, ไม่เหลือ fog, ไม่มีอะไรต้องตัดสินใจก่อนลงมือ. ตอนนั้น:

1. พูดออกมาตรง ๆ ว่า map จบแล้ว
2. สรุป spec จาก Decisions so far → เป็น input ให้ฝั่ง build
3. ความต่อเนื่องของ build อยู่ที่ `HANDOFF.md` **ไม่ใช่** map — map ปิดไว้เป็นบันทึกว่า *ทำไม* ถึงเลือกทางนี้

ไม่ต้องรอ map จบทั้งใบก็ส่งต่อได้ ถ้า slice หนึ่งมี decision ครบแล้ว — แต่ต้องบอกชัดว่าส่งต่อ slice ไหน

- `prototype` → artifact เล็กที่สุดที่ react ได้ ติดป้าย disposable
- `grilling` ✅ / `domain-modeling` ✅ / `leancode` ✅ / `wayfinder` ✅ มีครบ
